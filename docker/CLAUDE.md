# Docker runtime (`docker/`) — working notes for Claude

This is the **runtime** side of deployment: the generated `docker-compose.yaml` + `.env`, the `config/` tree bind-mounted into every container (tracked `cyclonedds.xml`, runtime `mowgli_robot.yaml`), the standalone `stack.sh` stack manager, the simulation/Foxglove compose overrides, and field-session logs + ad-hoc analysis scripts under `logs/`.
It owns **no compose fragment source** (`install/compose/*.yml`), **no `.env` key definition** (`install/lib/env.sh`), **no parameter default** (`ros2/src/mowgli_bringup/config/`) and **no ROS node**. Nearly everything here is generated by `install/` or is gitignored runtime state — change the producer, never the product.

## Build · test · run

```bash
# Stack straight from this checkout (regenerates docker-compose.yaml from docker/.env)
cp docker/.env.example docker/.env                       # first time only
./docker/stack.sh regen | up | down | restart | pull | update | ps | config
./docker/stack.sh logs -f mowgli
./docker/stack.sh <anything else>                        # passthrough to `docker compose`

# Full host install / upgrade / diagnose (owns udev, UARTs, image pull)
bash install/mowglinext.sh
bash install/mowglinext.sh --check

# The only guards over what this directory holds — run them by hand (no CI does)
bash install/tests/test_compose_validity.sh
bash install/tests/test_env_output.sh
bash install/test_mowglinext.sh

# Simulation (Webots; built from ros2/Dockerfile target `simulation`)
docker compose -f docker/docker-compose.simulation.yaml build
docker compose -f docker/docker-compose.simulation.yaml up dev-sim         # live source bind-mounts
docker compose -f docker/docker-compose.simulation.yaml up simulation-gui  # noVNC on :6080
docker compose -f docker/docker-compose.simulation.yaml exec dev-sim \
  bash -c "source /ros2_ws/install/setup.bash && python3 /ros2_ws/src/e2e_test.py"

# Standalone Foxglove container (set enable_foxglove:=false on `mowgli` first)
docker compose -f docker/docker-compose.yaml -f docker/docker-compose.foxglove.yaml up -d
```

On a real robot the installer also drops `mowgli-up/-down/-restart/-logs/-ps/-check/-pull/-gps-logs/-lidar-logs/-shell/-status` into `/usr/local/bin` (`install/lib/tools.sh` L134–205); they `cd` into the install's `docker/` and call `docker compose`.

## Conventions

- **Never hand-edit** `docker-compose.yaml`, `.env`, `config/mowgli/mowgli_robot.yaml`, `config/mqtt/mosquitto.conf`, `config/om/mower_config.sh` — generated/runtime and gitignored. Edit `install/compose/*.yml`, `install/lib/env.sh`, or `install/config/`, then `./docker/stack.sh regen`.
- `write_compose_merged` runs `docker compose config --no-interpolate`, so `${MOWGLI_ROS2_IMAGE}` stays a literal in the merged output; the pure-Bash fallback (`install/lib/compose.sh` L169–206) is a naive section-concatenator.
- New `.env` key → default in `install/lib/env.sh` `setup_env`, **whitelist in `install/lib/state.sh is_allowed_installer_key`** (or presets/reloads drop it silently), then `install/tests/test_env_output.sh` and `.env.example`.
- Compose style: 2-space YAML, the shared `x-ros2-env` anchor for the ROS env block, `container_name: mowgli-*`, `network_mode: host` + `ipc: host`, json-file logging capped with `max-size`/`max-file`.
- `logs/*.py` and `logs/mow_sessions/*.py` are throwaway field tools, not shipped code — no formatter/linter config covers them and no CI path builds them.

## Component-specific gotchas

- **No CI workflow watches `docker/**`.** Nothing here is built, linted, or validated automatically; `install/tests/test_compose_validity.sh` is the only check on the generated compose and it never runs in CI.
- `README.md` is partially stale: it still documents SLAM Toolbox / `slam_mode` / `slam_toolbox.yaml` and the dual EKF (both removed — root Invariants 1–2), plus `docker-compose.ser2net.yaml` / `.remote.pi.yaml` / `.remote.host.yaml` and a `docker.yml` CI workflow, **none of which exist**.
- `config/mowgli/README.md`'s "Additional overrideable files" table is fiction: only `mowgli_robot.yaml` is read from that mount (`ros2/src/mowgli_bringup/launch/robot_config_util.py` L31). A `nav2_params.yaml` / `localization.yaml` / `hardware_bridge.yaml` dropped in here is ignored.
- Same README calls the mount read-only; it is **rw** for `mowgli` (`install/compose/docker-compose.base.yml` L52) so calibration can splice `dock_pose_*`, `datum_*`, `imu_yaw` back into the yaml (root Invariant 6). `gps` and `ntrip` mount it `:ro`.
- `config/cyclonedds.xml` is listed in `.gitignore` but is **tracked** — a clone already has it, so the installer's seed-if-absent guard never fires and the stack mounts THIS file. Edit it **and** `install/config/cyclonedds.xml`.
- That file pins DDS to `lo` with `AllowMulticast=false` on purpose: letting Cyclone autodetect the NIC routes DDS over WiFi/Ethernet and kills GPS/RTK (issue #418). `MaxAutoParticipantIndex: 500` exists because the full stack starts 35+ participants.
- `fastdds.xml` is reference-only — nothing mounts it, Cyclone DDS is mandatory (root "What NOT to Do"). Do not wire it in.
- `COMPOSE_PROJECT_NAME` (default `install`) must stay stable: renaming it orphans the `install_mowgli_maps` volume holding `areas.dat` and the persisted fusion graph.
- `stack.sh` re-asserts `REPO_DIR`/`DOCKER_DIR` **after** sourcing `install/lib/config.sh` (L76–83), because config.sh recomputes them from `MOWGLI_HOME` at source time. Any new lib that caches a path at source time needs the same treatment.
- `stack.sh` drops `mqtt`/`watchtower` unless `ENABLE_MQTT`/`ENABLE_WATCHTOWER` are `true` (L88–103), but the **full installer always composes both** — a `stack.sh` stack is not service-identical to a real robot's.
- `docker-compose.simulation.yaml`'s header comments say "Gazebo"; the simulator is **Webots**. The `Xvfb` / `DISPLAY=:99` part of the command is still real.
- `dev-sim` bind-mounts `ros2/src/**/{config,launch,trees,worlds}` over the installed share dirs — edits apply on container restart, but a stale mount silently shadows a freshly rebuilt package.
- `logs/mow_sessions/patch_dwb.py`, `splice_dwb_source.py`, `square_test.py` target a single `nav2_params.yaml` and DWB/MPPI. Both are gone (params are base + overlay; coverage is FTCController — root Invariant 8). Historical artefacts, they will not run as written.
- `logs/mow_sessions/*.jsonl` is gitignored; the session monitor writes inside the container, so redirect to `/ros2_ws/maps` (the named volume) or bind-mount this directory — see `../docs/claude/session-monitoring.md`.
- `LIDAR_ENABLED` in `.env` only decides whether the `mowgli-lidar` **container** is composed; the ROS stack's LiDAR mode is `mowgli_robot.yaml:lidar_enabled` (`install/compose/docker-compose.base.yml` L13–17).
- A prior `compose up` with a missing host path leaves Docker's auto-created **directory** squatting a file bind mount (`config/cyclonedds.xml`, `config/mqtt/mosquitto.conf`) — DDS then silently ignores the unreadable URI and falls back to defaults. `ensure_default_configs` self-heals it (`install/lib/compose.sh` L30–48); re-run `./docker/stack.sh regen` rather than deleting by hand.
- `migrate_runtime_paths` backs up `.env` and `docker-compose.yaml` to `.old.<timestamp>` here on **every** installer run (`install/lib/deploy.sh` L279–280); they accumulate and are gitignored.

## Safety

Compose files here pass `/dev` into privileged containers and start the stack that drives the blades and wheels — a wrong device mapping, a dropped `cyclonedds.xml` mount, or a renamed service is a physical-behaviour change. Read the root **Safety** section and Invariant 9 first, flag such edits as safety-critical in PR reviews, and never add a software e-stop path here: the STM32 firmware is the sole blade/e-stop authority.
