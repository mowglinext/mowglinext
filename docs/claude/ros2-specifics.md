# ROS2 Specifics

> Detailed elaboration of the localizer, navigation, and coverage stack. The must-not-violate rules live in [`../../CLAUDE.md`](../../CLAUDE.md) (Architecture Invariants + What NOT to Do); this file is the reference detail behind them, loaded on demand.

- **Distro:** Kilted
- **DDS:** Cyclone DDS (all containers share `docker/config/cyclonedds.xml`)
- **Topics:** Mowgli-specific topics under `/mowgli/` namespace
- **Frames:** `map` (global, GPS-anchored via fixed datum), `odom` (continuous local, dead-reckoning only — never jumps), `base_footprint` (robot frame for Nav2), `base_link` (rear axle), `lidar_link`, `imu_link`
- **TF chain:** `map→odom` AND `odom→base_footprint` are **both** published by `fusion_graph_node` (broadcast from its dedicated TF thread; `map→odom` absorbs GPS corrections, `odom→base_footprint` is continuous dead-reckoning) — per Invariant 2, do NOT publish either from any other node. `base_footprint→base_link` (static), `base_link→sensors` (static — `base_link→imu_link` rotation = `imu_yaw/pitch/roll` from `mowgli_robot.yaml`, auto-calibratable via GUI button)
- **Units:** SI throughout (metres, radians, seconds)
- **Sensor fusion:** `fusion_graph_node` (GTSAM iSAM2 Pose2 graph) is the sole localizer — it publishes BOTH `map→odom` AND `odom→base_footprint`. One node per `node_period_s`; factors: a wheel between-factor (non-holonomic σ_y << σ_x, fed by `/wheel_odom`), a gyro between-factor on yaw, a custom `GnssLeverArmFactor` (analytic Jacobian — antenna lever-arm rotates with node yaw) fed by **`/gps/fix`, subscribed directly** (the node does its own datum projection via `LatLonToMap`; it does NOT consume `/gps/pose_cov`), and unary yaw factors for COG (`/imu/cog_heading`) and tilt-compensated mag (`/imu/mag_yaw`, when calibrated); optional LiDAR scan-matching/loop-closure factors gated by `use_scan_matching`/`use_loop_closure`. Config in `ros2/src/fusion_graph/config/fusion_graph.yaml`. The wheel-vs-gyro **slip veto** (zeroes a node's wheel translation when the encoders claim a rotation the gyro does not see) is evaluated over a sliding window of `slip_window_s` (0.5 s, `slip_window.hpp`, pure + unit-tested) — the per-node gate could not tell one encoder tick of L/R asymmetry (≈ 0.011 rad per 40 ms frame) from genuine slip (≈ 0.012 rad/frame, sustained) and fired 1.33/s on straight swaths, silently dropping ~5 % of dead-reckoned travel (issue #516). The three yaml thresholds keep their per-node meaning (the window sums and scales), a cold window never vetoes, and `slip_window_s: 0` is the old per-node gate exactly; do not raise the per-frame thresholds instead, which also blinds it to the real 2026-05-27 case. Absolute yaw comes from `cog_to_imu_node.cpp` (GPS course-over-ground, gated on BOTH `wheel_omega` AND IMU `gyro_z` for `on_fix` and `republish_latched_when_stationary` — wheel-only gating let multi-degree COG yaw jumps slip through during PRE_ROTATE tight arcs, because the Webots kinematic-drive simulation can under-report `wheel.angular.z` while the IMU still sees real angular motion) and `mag_yaw_publisher_node.cpp` (tilt-compensated magnetometer yaw, when magnetometer is calibrated). The `hardware_bridge_node` runs a ~2 s IMU bias calibration (`imu_cal_samples: 200` at the 90 Hz IMU packet rate — `mowgli.launch.py` injects the `mowgli_robot.yaml` value, which wins over `hardware_bridge.yaml`'s stale 1000) on every dock transition, periodically while docked (`imu_cal_periodic_recal_sec`) and off-dock once stationary (`imu_cal_auto_rest_sec`), and logs the implied mounting pitch/roll so the operator can promote any >1° offset into `mowgli_robot.yaml` → `imu_pitch/imu_roll`. A **dead-IMU guard** (`mowgli_hardware/imu_liveness.hpp`, pure + unit-tested) watches the raw packets: |accel| below `kMinPlausibleAccelMps2` (3 m/s² — gravity is never zero) for 45 consecutive samples (0.5 s) logs a throttled ERROR, a completed calibration window whose mean |accel| is not gravity or whose gyro variance is exactly zero on every axis is **discarded, not persisted** (the previous cal is kept), and a persisted `imu_calibration.txt` whose five covariances are all exactly 0 is rejected at load. Detection only — nothing gates on it yet (field case 2026-09-02: a hung WT901 bus streamed exact zeros, the bridge accepted + persisted an all-zero cal and wiped the real gyro bias).
- **Navigation:** `FollowCoveragePath` = `mowgli_nav2_plugins/FTCController` (deterministic Follow-the-Carrot; decoupled lon/lat/ang PID with a low-pass on the derivative; one `PRE_ROTATE` pivot then tracks the continuous `full_path`; lateral obstacle avoidance via `enable_obstacle_deviation`). FTC's obstacle detection is **zone-masked** (`ignore_obstacles_outside_zone`, issue #517): the global keepout costmap it already holds for `confine_deviation_to_zone` (`ObstacleDeviation::BoundaryGuard`) is reused in the opposite direction, so a lethal local-costmap cell that is also lethal in the keepout (outside the area, or inside a keepout hole) is not an obstacle for the deviation logic — the path ends `chassis_safety_inset` short of the boundary and U-turns there, so the lookahead footprints reach the hedge the boundary was recorded along at every row end (71 strip aborts in one 73-min mow). In-zone obstacles keep the exact previous behaviour, the out-of-zone rejection of lateral OFFSET candidates is unchanged, and collision_monitor stays the real-time guard. The lookahead window is already clipped at the plan end (`[current_index_, min(size, current_index_ + obstacle_lookahead))`); poses past the last one are never sampled. `FollowPath` (transit) = RotationShim + RPP. FTC was restored 2026-06-19, reverting an MPPI experiment (MPPI cut corners at U-turns and weaved on the straights).
- **Coverage:** Two-package pipeline. `map_server_node` (`mowgli_map`) owns area polygons + the `mow_progress` grid layer. `coverage_server` (`mowgli_coverage`, action `plan_coverage` = `mowgli_interfaces/action/PlanCoverage`) runs a deliberately minimal F2C v3 pipeline in `planBoustrophedon()` (`coverage_planning.cpp`): a `chassis_safety_inset − op_width/2` field offset (F2C places the outermost pass `op_width/2` inside the planning cell in BOTH generators, so the offset — not `chassis_safety_inset` itself — is what puts the outermost DRIVEN centreline `chassis_safety_inset` inside the recorded line); positive (the shipped default: inset 0.20 > op_width/2 = 0.08) = `ConstHL::generateHeadlands(field_offset)` shrink, negative (inset < op_width/2) = `expandCellOutward()` so ring 0 rides ON the recorded line, and it is floored at 0 only when the ring stage is disabled; then `ConstHL::generateHeadlandSwaths(op_width, n_rings, out2in)` concentric mowed rings (`num_headland_passes` is a THREE-WAY sentinel: `<0` = NONE — the whole headland stage is SKIPPED, `0` = auto = ceil(headland/op_width) floored at 1, `>0` = exactly that count); `ConstHL::generateHeadlands(n_rings*op_width)` mainland — with n = 0 the mainland is simply the inset field (never `generateHeadlands(…, 0.0)`, which is a real GEOS buffer round-trip) and the connectors are bounded by that field EXACTLY, instead of by an outermost-ring centreline that no longer exists — on-edge swath ends are accepted by `allInside()`'s 1 mm tolerance rather than by expanding the ring outward, and the `chassis_safety_inset − op_width/2` field offset still applies (floored at 0) because F2C insets the outermost SWATH by `op_width/2` exactly as it insets ring 0 (#429); `BruteForce` swaths (fixed or auto angle; each disjoint clip of a sweep line is its OWN swath, so concave fields and holes need NO decomposition); `BoustrophedonOrder` serpentine. NO `pp::PathPlanning`, NO turn planners, NO OR-Tools genRoute, NO TrapezoidalDecomp. The plan is built from insets, so it is in-bounds by construction — but `buildContinuousSubPaths` still projects every pose that lies OUTSIDE the connector clearance ring back `kClearanceClampMarginM` (0.02 m) inside it via `clampInsideRing` before emitting the sub-path (issue #388: F2C's ring and clearance offsets round convex corners differently, and an out-of-bounds seg-1 start made the blade-off transit un-drivable, skipping the whole sub-path); poses already inside — or exactly ON the ring, where `pointInRing` is unstable — are untouched. Only a residual excursion past `coverage_server`'s `kBoundarySlackM` (0.05 m) verify slack is then counted and logged as a planner bug. Result = explicit per-segment `nav_msgs/Path[]` + types (ring|swath), plus one or more continuous, **hole-free** `drivable_subpaths` (rings+swaths joined by forward turn-around arcs of nominal radius `connector_turn_radius` — 0.18 default, read from `mowgli_robot.yaml` if the operator adds the key (it is NOT in the template; `navigation.launch.py:403` carries the fallback), clamped to `[min_turning_radius, 0.50]` at launch — from `buildContinuousSubPaths`), plus a concatenated `full_path` for the GUI. A hole-free field yields one sub-path (== `full_path`); a multi-hole field is split so each obstacle gap becomes a blade-off Nav2 transit, and sub-paths are ordered by a deterministic greedy nearest-neighbour pass to minimise that transit. One `PlanCoverageArea` per area per session; `FollowStrip` drives each sub-path with FTC (blade off during the inter-sub-path Nav2 transit) and resumes by pose cursor into the sub-path concatenation.
- **Coverage goal-checker:** `coverage_goal_checker` is `mowgli_nav2_plugins/PathProgressGoalChecker` (NOT `StoppedGoalChecker` — that one fires on velocity stoppage and matches mid-traversal during FTC's PRE_ROTATE pivots, which would complete the action at <2% coverage). It subscribes to `<plugin_name>/global_plan` (= `/controller_server/FollowCoveragePath/global_plan`) and only fires when the robot has monotonically tracked >= `progress_threshold` (0.95) of path poses AND is within xy/yaw tolerance of the goal pose. Includes a `fallback_timeout_s` watchdog (5 s) for missing global_plan and a `short_path_poses` guard (default 10): any plan of ≤ 10 poses — a tiny turn-connector or per-swath segment the 95 %-progress gate cannot register — completes on xy+yaw proximity to the goal alone. Nav2 sets `xy_goal_tolerance: 0.50` (matching FTC's `max_goal_distance_error`) and `yaw_goal_tolerance: 3.14` (≈π, i.e. final heading ignored — the perpendicular swaths already cover it).
- **Datum-change migration (issue #216):** all persisted geometry (areas.dat polygons, `dock_pose_x/y/yaw`) is map-frame metres anchored ONLY by `datum_lat`/`datum_lon`. `map_server_node` receives the datum at launch (same `robot_params` read as `navsat_to_absolute_pose`), stamps it into `areas.dat` on every save, and on load compares the stamp to the launch datum: on mismatch it re-projects every polygon + the dock pose old-ENU → WGS84 → new-ENU (`mowgli_interfaces/wgs84_projection.hpp` — the exact equirectangular math the localizer uses), splices the migrated dock pose back into `mowgli_robot.yaml`, and re-stamps `areas.dat`. So an operator moving the base / re-centring the datum keeps the map glued to the physical garden after the required restart. Unstamped legacy files are adopted as-is and stamped with the current datum; a 0/0 datum disables the whole mechanism. The persisted fusion_graph graph (`/ros2_ws/maps/fusion_graph.*`) is NOT migrated — its own cross-datum guard rejects it on load and the graph rebuilds. The saved occupancy grid (`map_file_path`, disabled by default) is not migrated either.
- **Area Recording:** `RecordArea` BT node samples the trajectory at `area_record_rate_hz` (10 Hz default, was 2 Hz; capped by the BT `tick_rate`), Douglas-Peucker simplification at `area_simplification_tolerance` (0.05 m), saves polygon via `/map_server_node/add_area`. Live preview on `~/recording_trajectory`.
- **Manual Mowing:** Dedicated BT state (COMMAND_MANUAL_MOW=7). Teleop via `/cmd_vel_teleop`, blade managed by GUI. Collision_monitor, GPS, and the `fusion_graph` localizer remain active.
- **Emergency Auto-Reset:** BT auto-resets emergency when robot placed on dock (charging detected). Firmware is safety authority.
- **Repeat-dig escalation (issue #500):** the wheel-slip dig detector of Invariant 16 (`mowgli_hardware/dig_detector.hpp`) keeps its per-event response exactly as it is — hard stop on the wire, bounded reverse, and a PENDING keepout stamped by `map_server`. What sits on top is a repeat detector (`mowgli_hardware/dig_escalation.hpp`, pure + unit-tested): `dig_escalate_count` (3) latches inside `dig_escalate_radius_m` (0.50) within `dig_escalate_window_s` (60) is not a dig to route around but an obstruction the robot cannot resolve, so the bridge latches a flag on `/hardware_bridge/dig_escalated` (`std_msgs/Bool`, TRANSIENT_LOCAL depth 1) and logs an ERROR. The bridge commands nothing extra — stopping the mission belongs to the BT's `DigObstructionGuard` (`IsDigEscalated` → blade off, `StopMoving`, `DIG_OBSTRUCTION` status, exempting charging/HOME/manual/recording so the operator can recover), and the flag clears only when the robot reaches the charger. Field capture 2026-09-04: 17 latches, five in 23 s inside a 6 cm square, then 5.5 min for 20 cm of progress against a physical object — the bounded reverse and the 0.60 m keepout both worked and neither could break the loop, because the next planned manoeuvre kept aiming the robot back at the same object.
- **GPS fusion:** `navsat_to_absolute_pose_node` reads `/gps/fix` (NavSatFix) and emits `/gps/pose_cov` (PoseWithCovarianceStamped in `map` frame) with covariance derived from `position_accuracy` and a lever-arm correction applied via the current map-frame yaw. `fusion_graph_node` does **not** subscribe to `/gps/pose_cov` — it takes raw `/gps/fix` and projects it itself inside `GnssLeverArmFactor` (with a bounded motion-consistent wrong-fix gate). `/gps/pose_cov` is consumed by `map_server_node` as the RTK-quality gate for `~/set_docking_point`; `/gps/absolute_pose` remains exposed for the GUI and BT. With RTK-Fixed (σ ~3 mm) and frequent updates, the graph converges to fix precision.
- **fusion_graph (sole map+odom localizer):** `fusion_graph_node` (GTSAM iSAM2) is launched **unconditionally** by `navigation.launch.py` — there is **no `use_fusion_graph` arg**, do not write one from the GUI. Pose2 graph; one node per `node_period_s`, with a wheel between-factor (non-holonomic σ_y << σ_x), a gyro between-factor on yaw, a custom `GnssLeverArmFactor` (analytic Jacobian — antenna lever-arm rotates with the node's yaw, so it couples to heading correctly), and unary yaw factors for COG and tilt-compensated mag. **LiDAR scan-matching between-factors and loop-closure factors are wired** (gated by `use_scan_matching` / `use_loop_closure`) — they let the map-frame estimate carry through multi-minute RTK-Float windows, which is why this design exists. **Loop closures are rate/travel-gated and σ-floored** (issue #513, `loop_closure_gate.hpp`, pure + unit-tested): because `lc_skip_when_rtk_fixed` disables LC under Fixed, the search runs exactly when GPS is Float or absent, where the `scan_yield` σ inflation never applies — measured 2026-09-02 at 13.7 accepted LC/s under Float (3816 in 286 s of mowing, 0 under Fixed), each a 5 cm factor to the *adjacent* swath on featureless grass, i.e. localization jumps. Now at most ONE LC is accepted per node and none until BOTH `lc_min_interval_s` (2 s) AND `lc_min_travel_m` (1 m of wheel travel) have accrued since the last ACCEPTED LC (accumulators reset on accept only — the opposite polarity of the RTK wrong-fix gate, reasoned in the header), and `lc_sigma_xy` is floored to `lc_gps_sigma_ratio` × the last accepted GPS σ so an LC can never out-vote the fix it runs beside; `/fusion_graph/diagnostics` reports `lc_rate_gated` next to `loop_closures`. **While `is_charging` the node suppresses live GPS factors and re-asserts a firm dock prior (`dock_reanchor_sigma_xy_m` 3 cm) at `dock_pose` once per node — but that prior is not unconditional** (issue #512, `dock_gps_consistency.hpp`, pure + unit-tested): a FRESH RTK-Fixed sample with σ ≤ `dock_prior_max_gps_sigma_m` (0.05) that puts the antenna more than `dock_prior_max_gps_disagreement_m` (0.50) from `dock_pose ⊕ R(yaw)·lever_arm` makes the prior yield for that node and the sample is fused instead, with a throttled ERROR and `dock_gps_disagreement_m` / `dock_prior_yielded` in the diagnostics (field case 2026-09-02: "Fixed 14–20 mm" at 1.88–2.45 m from the dock for ~45 min after a receiver power cycle, pinned silently). No fix / Float / large σ on the dock — the dock under a terrace — is deliberately NOT a trigger: the prior keeps pinning and nothing gates on the absence of a fix. Reads datum + lever-arm from `mowgli_robot.yaml` via `fusion_graph.launch.py`. Persists `<graph_save_prefix>.{graph,scans,meta}` (default `/ros2_ws/maps/fusion_graph.*`); auto-saves on RECORDING→IDLE, dock arrival, and every `periodic_save_period_s` (5 min) in AUTONOMOUS state. Surface: `/fusion_graph/diagnostics`, `/fusion_graph/markers`, `/imu/fg_yaw`, services `~/save_graph` + `~/clear_graph` (both `Trigger`).
- **IMU mounting calibration:** `base_link→imu_link` rotation (imu_roll, imu_pitch, imu_yaw in mowgli_robot.yaml) is critical — if wrong, gravity-removal leaks into pitch and yaw integration degrades. Use the GUI's "Auto-calibrate" button next to IMU Yaw — the robot drives itself ~0.75 m forward then back, three cycles (`N_CYCLES`, 0.5 m/s cruise), and solves `imu_yaw = atan2(-ay_chip, ax_chip)` from accel direction vs wheel-derived `a_body`; the same run also returns `imu_pitch`/`imu_roll` from the stationary segments. The `mag_only` request flag SKIPS those drive cycles and runs the figure-8 magnetometer pass instead (`CalibrateImuYaw.srv`).
- **Nav2 tuning:** Global costmap **70 m × 70 m** rolling window at 0.08 m (was 20×20 — a >31 m area-to-area goal fell outside the window and Smac rejected it as AREA_UNREACHABLE; size it ≥ 2× the longest per-axis transit); keepout_filter is **enabled in the GLOBAL costmap** (it makes the area boundary lethal to the Smac planner so transit never exits the authorised zone; the dock corridor is carved back to free in `map_server`) and **removed from the LOCAL costmap** (there it marked the boundary lethal and tripped "collision ahead" on edge swaths). collision_monitor's active gates are variant-specific: the LiDAR overlay runs `polygons: ["FootprintApproach", "PolygonStopNarrow", "PolygonSlow"]` — two velocity-projected `approach` stops plus a soft slowdown, and deliberately NO static `stop` box (a static box zeroes the whole twist regardless of direction and froze the reverse-escape, issue #393; the old full-chassis PolygonStop also kept firing on obstacles FTC had already skirted); the no-LiDAR overlay is pass-through (its polygons and the `scan` source are all `enabled: false`). Obstacle avoidance during coverage is FTC's lateral path deviation (`enable_obstacle_deviation`, reading the LiDAR `obstacle_layer`), with PolygonSlow as the soft-slowdown fallback; source_timeout **1.5 s** (was 5.0 — SAFETY_REVIEW_2026-07-23 A-C2: 5 s of stale scan let the robot mow blind for a full metre); PoseProgressChecker `required_movement_radius: 0.15` + `required_movement_angle: 0.5 rad` (counts rotation as progress so headland pivots don't trip "no progress"), `movement_time_allowance: 30s` default (operator-tunable via `progress_timeout_sec`); failure_tolerance 1.0; speeds default `transit_speed 0.2 / mowing_speed 0.2 m/s` from the `mowgli_robot.yaml` template (per-site overrides in the installed sparse file; `navigation.launch.py` injects them as `FollowPath.desired_linear_vel` and `FollowCoveragePath.speed_fast`, and derives `speed_slow` from `mowing_speed × turn_speed_ratio`).
- **Webots simulation:** the sim carries five load-bearing ODE workarounds (wheel-cylinder Pose rotation, the deliberate `(0, -1, 0)` HingeJoint axis, the teleport+`setVelocity` pair in `kinematic_drive.py`, `mode:=realtime` as the default, and the `<extern>`-controller body requirement). Read [`../WEBOTS_SIM.md`](../WEBOTS_SIM.md) **before** editing `worlds_webots/`, `protos/`, `urdf_webots/`, or `kinematic_drive.py` — each one presents as a Nav2 bug when broken.
- **Joystick:** Foxglove client passes `schemaName` in `clientAdvertise` for JSON-to-CDR conversion. GUI shows the joystick overlay while the BT state is `RECORDING` or `MANUAL_MOWING` (`MapPage.tsx`, `JoystickOverlay`).
